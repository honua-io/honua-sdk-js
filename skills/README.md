# Honua SDK agent skills

Procedural [agent skills](https://code.claude.com/docs/en/skills) that teach
coding and terminal agents to drive Honua correctly for a specific release. Each
skill is a directory with a `SKILL.md` whose YAML frontmatter carries `name`,
`description`, `release`, and `stages`, followed by a procedural body. The
`description` states *when* the skill applies, so a compatible agent can load it
on demand.

`release` pins the skill to a Honua release; `stages` names the
[zero-to-map journey](../docs/zero-to-map-release-journey.md) stage(s) it
serves (an empty list means the skill is not tied to a terminal stage).

## Available skills (release 2026.1)

Every skill declares the release it was written for and the zero-to-map journey
stage(s) it serves. `npm run verify:skills` fails when a skill drifts from the
release, cites a tool or file that does not exist, pins a package version this
repository does not publish, or leaves a journey stage with no skill.

## Drift gates

The table above and everything it claims are checked, not trusted:

```bash
npm run verify:skills   # frontmatter, release, stage coverage, tools, versions, secrets, README freshness
npm run skills:readme   # regenerate the managed table after adding or re-scoping a skill
```

`npm run verify:skills` fails when a skill's `release` is not the current
release, a journey stage has no skill, a body cites an `npm run` script, repo
file, or `honua_*` tool that does not exist, a body pins a package version this
repository does not publish, or a body contains a credential-shaped literal. The
optional registry lane
(`HONUA_SKILLS_REGISTRY_LIVE_ENABLED=true npm run verify:skills`) additionally
confirms each pinned version resolves on the public npm registry; it is never
part of PR CI.

## Install into Claude Code (or a compatible agent)

Skills are plain directories, so installing one is copying it to where your
agent looks for skills.

- **Personal (all projects):** copy a skill directory into `~/.claude/skills/`.

  ```bash
  cp -R skills/honua-sdk-quickstart ~/.claude/skills/
  ```

- **Project-scoped (checked in with the repo):** copy into `.claude/skills/` at
  your project root.

  ```bash
  mkdir -p .claude/skills && cp -R skills/honua-arcgis-migration .claude/skills/
  ```

Each skill keeps its own directory name (which must match the `name` in its
frontmatter — enforced by `npm run verify:skills`). Restart / reload the agent so
it re-scans the skills directory. Other MCP-compatible agents that support the
`SKILL.md` convention can consume the same directories.

## llms.txt

For agents that ingest an [llms.txt](https://llmstxt.org/) index rather than
skills, this repo also generates `llms.txt` (curated index) and `llms-full.txt`
(concatenated docs corpus) at the repo root via `npm run docs:llms`. Point your
assistant at those files to prime it with current APIs.

The same corpus backs the `honua_docs_search` MCP tool
(`mcp/src/tools/docs-search.ts`), which answers documentation questions from the
committed docs and returns file plus release-version citations.

## Context7 registration

The repo root ships a `context7.json` so [Context7](https://context7.com) parses
and serves this library's docs to coding agents. To (re)submit:

1. Confirm `context7.json` at the repo root is current (see the
   [Library Owners guide](https://context7.com/library-owners) for the schema).
2. Open <https://context7.com/add-library>, choose the GitHub tab, and paste the
   `honua-io/honua-sdk-js` repository URL.
3. Context7 reads `context7.json` (folders/excludes/rules) and indexes the docs,
   exposing the library as `/honua-io/honua-sdk-js`.

Library owners can instead claim the library to manage this configuration from
the Context7 admin panel.
