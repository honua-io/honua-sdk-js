# Honua SDK agent skills

Each skill here passed a paired evaluation: the same task, run by an agent with
and without the skill, against the live Maui County demo server
(`https://demo.honua.io`). The tasks came from the Maui demo requirements, and
an independent checker graded each outcome. The bars were preregistered
before the runs. Opus 5.5 and gpt-6.1-sol ran both arms in a sandbox that hid
everything except the task, and the skill had to pass every check and beat its
unaided run. Skills that missed the bar were deleted.

| Skill | Task | Opus 5.5, with vs without (median of 2 pairs, all checks passed) |
| --- | --- | --- |
| `build-a-map-app` | Maui parcel map: 51,000 parcels at county and town zoom, zoning and flood overlays with toggles, parcel card | 418 s, $0.53 vs 1,640 s, $2.28 |
| `connect-data` | OGC API Features prefix search, GeoServices spatial joins, PMTiles metadata | 85 s, $0.30 vs 162 s, $0.85 |

Verified against `@honua/sdk-js` 0.3.2 from npm. Receipts are attached to the
[`skills-evidence-2026.1-r1`](https://github.com/honua-io/honua-sdk-js/releases/tag/skills-evidence-2026.1-r1)
release: the preregistration and its amendments, prompts, checkers, server
fingerprints, and every run's redacted transcript, workspace and grade. They
are not stored in this repository.

## Install

- **Copy a skill:** copy `skills/<name>/` into `~/.claude/skills/` (personal) or
  `.claude/skills/` (project). Agents that read `.agents/skills/` take the same
  directories.
- **npm:** releases after this change ship `skills/` in the package, at
  `node_modules/@honua/sdk-js/skills/`.

## Drift gates

The table above and everything it claims are checked, not trusted:

```bash
npm run verify:skills   # frontmatter, release, stage ids, tools, versions, secrets, README freshness
npm run skills:readme   # regenerate the managed table after adding or re-scoping a skill
```

`npm run verify:skills` fails when a skill's `release` is not the current
release, a body cites an `npm run` script, repo file, or `honua_*` tool that
does not exist, a body pins a package version this repository does not publish,
or a body contains a credential-shaped literal. The
optional registry lane
(`HONUA_SKILLS_REGISTRY_LIVE_ENABLED=true npm run verify:skills`) additionally
confirms each pinned version resolves on the public npm registry; it is never
part of PR CI.

## llms.txt

For agents that ingest an [llms.txt](https://llmstxt.org/) index rather than
skills, this repo also generates `llms.txt` (curated index) and `llms-full.txt`
(concatenated docs corpus) at the repo root via `npm run docs:llms`. Point your
assistant at those files to prime it with current APIs.

The same corpus backs the `honua_docs_search` MCP tool
(`mcp/src/tools/docs-search.ts`), which answers documentation questions from the
committed docs and returns file plus release-version citations.

## Context7 registration

The repo root ships a `context7.json` so [Context7](https://context7.com) parses
and serves this library's docs to coding agents. To (re)submit:

1. Confirm `context7.json` at the repo root is current (see the
   [Library Owners guide](https://context7.com/docs/library-owners) for the schema).
2. Open <https://context7.com/add-library>, choose the GitHub tab, and paste the
   `honua-io/honua-sdk-js` repository URL.
3. Context7 reads `context7.json` (folders/excludes/rules) and indexes the docs,
   exposing the library as `/honua-io/honua-sdk-js`.

Library owners can instead claim the library to manage this configuration from
the Context7 admin panel.
